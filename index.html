💻 Creating Your Ubuntu Virtual Machine

For projects that use Laravel, WebSockets (Reverb), queue workers, or multiple APIs, deploying an Ubuntu VM gives total control.

1

Select Region & Image

• Region: Select (Asia Pacific) East Asia (Hong Kong).
• Image: Choose Ubuntu Server 24.04 LTS - x64 Gen2.
• VM Architecture: Select x64 (do not select ARM64).

🌏
Why East Asia instead of Southeast Asia? Trial and student subscriptions often encounter the error:
This size is currently unavailable in southeastasia for this subscription: NotAvailableForSubscription.
Selecting East Asia avoids data center capacity restrictions while providing optimal low-latency (~30–40ms ping) for the Philippines.
2

Recommended Sizing

• Standard_B1s (1 vCPU, 1 GB RAM) ➔ 100% Free for 12 months.
• Standard_B2as_v2 (2 vCPU, 8 GB RAM) ➔ $0.1050 USD/hr (~$76 – $78/month in East Asia). Fully deducted from your $200 credit with ~$122+ leftover!

3

Open Inbound Ports

In Networking / Firewall rules, allow: Port 22 (SSH), Port 80 (HTTP), Port 443 (HTTPS), and Port 8080 (WebSockets).

CONNECT VIA SSH
ssh -i /path/to/your_key.pem azureuser@<YOUR_PUBLIC_IP>

⚡ Fallback Guide: When Standard_B1s is Unavailable

During capstone, thesis, or major project development, students often encounter unexpected roadblocks when trying to launch the default Standard_B1s Ubuntu virtual machine. If your initial VM creation fails, do not panic—use this complete troubleshooting guide and the battle-tested Hybrid Architecture.

🚨
The 4 Common "B1s Unavailable" Bottlenecks:
  • Capacity Depletion: In regions like eastasia (Hong Kong), southeastasia (Singapore), and japaneast, Standard_B1s is frequently grayed out or displays "Size not available in this region" due to high global cloud demand.
  • Student Quota Limits (0 vCPUs): Certain student subscriptions have their regional vCPU quota set to 0 specifically for the classic Standard BS Family.
  • Portal Pricing Display Confusion: The VM catalog displays retail pricing (e.g., ~$10.40/month) instead of $0.00. Azure deducts the 750 free hours credit automatically on your monthly statement rather than zeroing out catalog cards.
  • 1 GiB Memory Bottleneck: Even when successfully deployed, 1 GiB of RAM frequently runs out of memory (OOM) under multi-process stacks (Nginx + PHP 8.3-FPM + MySQL + Laravel Reverb WebSockets + Queue Workers).

Option 1: Newer 12-Month Free Cloud VM Sizes

If you require a 100% cloud-hosted virtual machine, Microsoft officially expanded the 12-month free compute tier beyond Standard_B1s to include newer modern architectures:

VM Size Processor Architecture vCPUs RAM 12-Month Free Quota
Standard_B2ats_v2 AMD EPYC 7763v (x86_64) 2 vCPUs 1 GiB 750 hrs / month Free
Standard_B2pts_v2 Ampere Altra (ARM64) 2 vCPUs 1 GiB 750 hrs / month Free
Standard_B1s Intel Xeon (x86_64) 1 vCPU 1 GiB 750 hrs / month Free
💡
Pro-Tip for Sizing Picker: If Standard_B1s is grayed out or unavailable in East Asia, search for B2ats_v2 (AMD). It provides 2 burstable vCPUs instead of 1, runs on standard x86_64 Linux, and qualifies for the exact same 750 free monthly hours.

Option 2: The Recommended Solution — The Hybrid Architecture

When cloud VM capacity is completely saturated or your backend stack demands significantly more memory (8 GB – 16 GB+) for WebSockets, background queues, and concurrent traffic, adopt the high-performance Hybrid Architecture:

Step-by-Step Hybrid Setup Guide

1

Provision the Azure Database (MySQL Flexible Server)

1. In the Azure Portal, search for Azure Database for MySQL flexible servers and click Create.
2. Compute Tier: Select Burstable.
3. Compute Size: Choose Standard_B1ms (1 vCore, 2 GiB RAM — fully eligible for 12 months free).
4. Storage: Set to 32 GiB.
5. Networking: Check "Allow public access from any Azure service within Azure to this server". Add your local IP address, or allow 0.0.0.0 - 255.255.255.255 with a strong admin password for team/mobile development.
6. In your Laravel backend .env file, connect with SSL enabled:

LARAVEL .ENV (AZURE MYSQL FLEXIBLE SERVER)
DB_CONNECTION=mysql DB_HOST=your-server-name.mysql.database.azure.com DB_PORT=3306 DB_DATABASE=your_database_name DB_USERNAME=your_admin_user DB_PASSWORD=your_secure_password MYSQL_ATTR_SSL_CA=/etc/ssl/certs/ca-certificates.crt
2

Deploy Frontends to Azure Static Web Apps (Free Forever)

1. Push your React / Vite frontend repository to GitHub.
2. In the Azure Portal, create an Azure Static Web App.
3. Select the Free Plan.
4. Under Deployment Details, connect your GitHub account, repository, and branch (main).
5. Set Build Preset to Vite (App location: frontend or root, Output location: dist).
6. Add your custom domain under the Custom domains blade; Azure automatically provisions and manages an edge SSL certificate at no charge.

3

Run the Backend on Local Hardware (WSL2 Ubuntu)

On your local development machine, install PHP 8.3, Composer, Nginx, and Supervisor inside WSL2:

WSL2 / UBUNTU TERMINAL
sudo apt update sudo apt install -y php8.3-fpm php8.3-cli php8.3-mysql php8.3-xml php8.3-mbstring php8.3-curl nginx supervisor

To ensure WebSockets (Laravel Reverb) and queue workers stay running 24/7 without terminal window dependence, configure a supervisord daemon at /etc/supervisor/conf.d/laravel-reverb.conf:

/etc/supervisor/conf.d/laravel-reverb.conf
[program:laravel-reverb] process_name=%(program_name)s_%(process_num)02d command=php /path/to/project/backend/artisan reverb:start autostart=true autorestart=true user=pheinz redirect_stderr=true stdout_logfile=/var/log/reverb.log
4

Expose Local APIs Using Cloudflare Tunnels (cloudflared)

To allow remote web visitors, judges, and mobile Expo apps to reach your local backend API without port forwarding, router configuration, or static public IPs, install Cloudflare Tunnel:

INSTALL & CONFIGURE CLOUDFLARE TUNNEL (WSL2)
# 1. Download and install cloudflared curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb sudo dpkg -i cloudflared.deb # 2. Authenticate and create your tunnel cloudflared tunnel login cloudflared tunnel create thesis-tunnel

Create your tunnel configuration file at ~/.cloudflared/config.yml:

~/.cloudflared/config.yml
tunnel: <TUNNEL_UUID> credentials-file: /home/pheinz/.cloudflared/<TUNNEL_UUID>.json ingress: - hostname: api.yourdomain.app service: http://localhost:8000 - hostname: ws.yourdomain.app service: http://localhost:8080 - service: http_status:404

Start the tunnel daemon:

RUN TUNNEL DAEMON
cloudflared tunnel run thesis-tunnel
🌐
Why Cloudflare Tunnel Solves Student Internet Issues: Philippine ISPs (Converge, PLDT, Globe) and mobile LTE/5G hotspots operate behind Carrier-Grade NAT (CGNAT), which blocks traditional router port forwarding. Cloudflare Tunnel establishes an outbound TLS connection to Cloudflare's global edge network, delivering instant SSL termination and full WebSocket compatibility from anywhere.

Best Practices for Presentation & Defense Day

1. Prevent Laptop Sleep

Use Windows PowerToys "Awake" utility or configure Windows Power & Sleep to "Never sleep when plugged into AC power" so your backend and tunnels never drop while presenting.

2. Automated Cloud Backups

Set up a cron job or scheduled script to run mysqldump from your laptop directly to Azure Blob Storage or a private GitHub repository to ensure zero data loss.

3. Production Caching

Before handing the demo to panelists, always run php artisan config:cache, php artisan route:cache, and php artisan view:cache to optimize response times.

Supabase gives you a production-grade PostgreSQL database with a beginner-friendly spreadsheet-like table editor (no SQL CLI needed), built-in user authentication, and instant connection strings for any backend framework.

🟣 Render — Free Backend APIs (Node / Python / Go)

Render allows juniors to host backend servers (Express, NestJS, FastAPI, Flask, Django) directly from a GitHub repository without configuring Linux servers, Nginx, or SSL certificates.

1

Prepare Your Code (Dynamic Port & 0.0.0.0 Binding)

Render injects a dynamic PORT environment variable into your container. Your code must read this variable and listen on all interfaces (0.0.0.0):

Node.js / Express — server.js or index.js
const express = require('express'); const app = express(); const PORT = process.env.PORT || 5000; app.get('/api/health', (req, res) => { res.json({ status: 'ok', timestamp: new Date() }); }); app.listen(PORT, '0.0.0.0', () => { console.log(`Server listening on port ${PORT}`); });
2

Create a New Web Service on Render

  1. Go to render.com and sign in with GitHub (no card required).
  2. Click New + at the top right and select Web Service.
  3. Connect your GitHub backend repository.
  4. Set up the build parameters:
    • Runtime: Node (or Python 3)
    • Build Command: npm install (or pip install -r requirements.txt)
    • Start Command: npm start (or uvicorn main:app --host 0.0.0.0 --port $PORT)
    • Instance Type: Select Free
3

Configure Environment Variables (Link Supabase)

In the Environment section, add your secrets:

  • DATABASE_URL = Paste your Supabase URI connection string
  • JWT_SECRET = Any private secret key
  • NODE_ENV = production

Click Deploy Web Service. In 2 to 3 minutes, Render issues a free live HTTPS URL:
https://<your-app>.onrender.com

⚡
The Render "Cold Start" Wake-up Hack (Must Read for Juniors) Free Render instances automatically spin down to sleep mode after 15 minutes of inactivity. When a new request arrives, Render needs 40 to 50 seconds to spin the container back up.

Presentation Hack: Open your backend health URL (e.g. https://my-api.onrender.com/api/health) in your browser or phone 2 minutes before your professor tests the project. Once woken, the API responds with zero lag throughout your presentation!
📁
Warning on File Uploads (Ephemeral Filesystem): Render free instances have ephemeral disks. If your app saves uploaded images to a local folder like ./uploads with Multer, those files will disappear on redeploy or spin-down.
Cardless Free Solution: Use Supabase Storage (1 GB free bucket) or Cloudinary (25 GB free tier) to store uploaded images and keep only image URLs in your database.

🔌 Connecting the Stack & Fixing CORS Errors

The #1 issue junior developers face when deploying frontend (Vercel) and backend (Render) on different domains is the infamous Cross-Origin Resource Sharing (CORS) error in the browser console:

🚫
The Classic Junior Error: Access to XMLHttpRequest at 'https://my-api.onrender.com/api/users' from origin 'https://my-app.vercel.app' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.

The Copy-Paste Fix for Node.js / Express:

server.js (Install: npm install cors)
const express = require('express'); const cors = require('cors'); const app = express(); // Allow frontend domains to call this backend API app.use(cors({ origin: '*', // For student prototypes/demos; or specify: ['https://my-frontend.vercel.app'] methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH', 'OPTIONS'], allowedHeaders: ['Content-Type', 'Authorization'] })); app.use(express.json());

The Copy-Paste Fix for Python / FastAPI:

main.py (FastAPI CORSMiddleware)
from fastapi import FastAPI from fastapi.middleware.cors import CORSMiddleware app = FastAPI() app.add_middleware( CORSMiddleware, allow_origins=["*"], # Or specify ["https://my-frontend.vercel.app"] allow_credentials=True, allow_methods=["*"], allow_headers=["*"], )

❓ Frequently Asked Questions

Q: Can juniors deploy to Supabase and Render without entering any credit or debit card?

Yes, 100%! Neither Render, Supabase, Vercel, nor Netlify ask for card details on their free tiers. Students can sign up with their standard GitHub accounts and deploy immediately.

Q: Why did my Render backend take 50 seconds to respond on presentation day?

Free Render instances spin down after 15 minutes of inactivity. When a request hits a sleeping container, Render takes 40–50 seconds to wake it up (cold start). Tip: Simply open your backend URL in your phone or browser tab 2 minutes before demonstrating to your instructor.

Q: Why is my Supabase database throwing connection errors after a week of not using it?

Supabase automatically pauses inactive free projects after 7 days without queries. Log into your Supabase dashboard and click Restore Project. It restores all tables and data within 1–2 minutes.

Q: Why is my Vercel frontend getting "CORS blocked" errors when calling my Render backend?

Browsers block cross-domain requests unless your backend explicitly authorizes them. In your Express backend, install cors and add app.use(cors()) before your routes (see the CORS guide above).

Q: Why did Azure charge $1.01 USD (~₱60 PHP) on my card?

That is a standard temporary authorization hold to verify your card is active. It is completely reversed/refunded back to your balance shortly after verification.

Q: Why does Azure say "This size is currently unavailable in southeastasia"?

Southeast Asia (Singapore) often has high data center utilization, causing quota restrictions for trial subscriptions. Simply switch your Region to East Asia (Hong Kong) and confirm architecture is x64 to unlock instant availability.

Q: Will my debit card be charged automatically on Azure?

Only if you exceed your $200 credit and free-tier quotas on a Pay-As-You-Go subscription. Having a Budget Alert ensures you get warned before charges occur.

Q: Do I need to buy a custom domain?

No! Vercel gives you free *.vercel.app, Render gives *.onrender.com, and Azure gives *.azurestaticapps.net (all with automatic HTTPS). You also get free .me domains from the GitHub Student Developer Pack via Namecheap.

Q: Can multiple students share one Azure VM?
